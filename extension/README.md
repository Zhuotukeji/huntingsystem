# 觅才 BOSS 寻访助手 V0.4

## 安装

1. 启动觅才后台，推荐使用 `pnpm dev --port 3010`；插件会先检测 3010，再检测 3000。
2. 在后台“数据源与设置”中配置至少 10 位的插件访问码；使用截图前还需配置 Sub2API 并启用截图分析。
3. 打开 `chrome://extensions`，启用开发者模式。
4. 选择“加载已解压的扩展程序”，指向仓库的 `extension/` 目录，或指向分发 ZIP 的解压目录。
5. 点击扩展图标，在侧边栏使用工作邮箱和插件访问码登录。

## 日常闭环

- 领取 AI 生成的搜索任务，复制关键词并手工打开 BOSS。
- HR 主动点击后，插件只截取当前可见的 BOSS 页面；发送到 Sub2API 前会再次确认。
- 评分结果同时显示证据和未知项，招呼语只生成可复制草稿，不自动发送。
- 回填结果人数、符合画像人数和有效沟通人数，系统据此小步更新搜索权重。
- 在“扫描简历”中打开一位候选人的 BOSS 详情并回到顶部，点击“开始扫描”，用 20-40 秒匀速滚动到底部，再点击“完成扫描并识别”。
- 插件优先使用临时标签页画面流，兼容模式下定时截取当前可见页；本地只保留变化关键帧，不生成或上传视频文件。
- 扫描最长 60 秒。完成时从临时画面中均匀选出最多 10 帧，逐帧发送至 Sub2API，随后校验候选人姓名、移除重叠和联系方式，合并为永久简历并创建增量学习任务。
- 真实 BOSS 页面在开始时确认一次本次扫描范围和用途。识别失败时可直接重试内存中的关键帧；成功、取消或关闭侧边栏后立即释放图片。

## 合成验收

插件设置中可打开内置的合成长简历页面。该页面不含真实候选人数据，可用于验证开始/完成扫描、关键帧筛选、重叠合并和永久入库链路。

## 权限边界

插件没有 content script，不读取 BOSS DOM、Cookie、账号、密码或验证码，不自动搜索、滚动、翻页、打开候选人或发送消息。`tabCapture` 和 `activeTab` 仅用于 HR 主动开始的当前标签页扫描；关键帧不在后端文件、数据库、Chrome 存储或日志中持久化。当前分发版只允许访问 `localhost` 和 `127.0.0.1` 后端。

## 检查与打包

```bash
pnpm extension:assets
pnpm extension:check
pnpm extension:pack
```

打包产物为 `artifacts/hunting-extension-v0.4.0.zip`，SHA-256 位于同名 `.sha256` 文件。
