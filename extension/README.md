# 觅才 BOSS 寻访助手 V0.7

## 正式安装

1. 将插件发布到 Chrome Web Store，可选择“未公开”分发。
2. 在觅才后台“数据源与设置”的“商店发布配置”中保存商店详情页地址。
3. HR 在后台点击“安装到 Chrome”，并完成 Chrome 要求的一次确认。
4. 返回设置页后，系统会检测插件是否安装及版本是否匹配。

Chrome 不允许普通网页静默安装 ZIP 或未上架扩展，因此商店发布是非受管设备实现简洁安装的必要前提。

## 本地开发安装

1. 启动觅才后台：`pnpm dev`。插件只检测 `localhost:3000`。
2. 在后台“数据源与设置”中配置至少 10 位的插件访问码；使用截图前还需配置 Sub2API 并启用截图分析。
3. 打开 `chrome://extensions`，启用开发者模式。
4. 选择“加载已解压的扩展程序”，指向仓库的 `extension/` 目录，或指向分发 ZIP 的解压目录。
5. 点击扩展图标，在打开的独立工具窗口中使用工作邮箱和插件访问码登录。再次点击图标会聚焦已有窗口，不会重复创建。

## 日常闭环

- 领取 AI 生成的搜索任务，复制关键词并手工打开 BOSS。
- HR 主动点击后，插件只截取当前可见的 BOSS 页面；发送到 Sub2API 前会再次确认。
- 评分结果同时显示证据和未知项，招呼语只生成可复制草稿，不自动发送。
- 回填结果人数、符合画像人数和有效沟通人数，系统据此小步更新搜索权重。
- 在“扫描简历”中打开一位候选人的 BOSS 详情并回到顶部，点击“开始扫描”。若工具窗口显示“等待授权”，保持该候选人页为活动页并点击一次浏览器工具栏中的觅才助手图标，工具窗口会自动继续；之后每滚动到一个需要保留的位置点击“截取当前帧”，最后点击“完成扫描并识别”。
- 插件使用 `tabCapture` 按标签页 ID 定向捕获经过地址校验的原始 Chrome 窗口当前活动 BOSS 标签页，并在工具窗口显示不计入帧数的取景预览供人工核对；不会弹出画面选择器，也不会捕获工具窗口。
- 扫描最长 60 秒。完成时从临时画面中均匀选出最多 10 帧，逐帧发送至 Sub2API，随后校验候选人姓名、移除重叠和联系方式，合并为永久简历并创建增量学习任务。
- 真实 BOSS 页面在开始时确认一次本次扫描范围和用途。识别失败时可直接重试内存中的关键帧；成功、取消或关闭工具窗口后立即释放图片。

## 合成验收

插件设置中可打开内置的合成长简历页面。该页面不含真实候选人数据，可用于验证开始/完成扫描、关键帧筛选、重叠合并和永久入库链路。

## Chrome Web Store 审核模式

首次打开插件后，审核员可以点击“进入商店审核演示”，无需工作邮箱、插件访问码、本地后台、Sub2API Key 或 BOSS 账号。

- 插件使用内置的合成人才画像和两条合成搜索任务，任务领取、关键词复制、延期和反馈在当前插件会话中完成。
- “打开演示页”只打开插件自带的合成长简历，不访问 BOSS。
- “分析当前演示页”会真实截取当前可见页，但只在插件内存中校验截图并返回明确标注的合成判断，不连接后台或 Sub2API。
- 招呼语使用固定合成草稿，不自动发送。
- 简历扫描复用正式模式的活动标签页截图和按钮逐帧采集；完成后在本地生成合成结构化摘要，关键帧立即从内存清除，不上传、不入库。
- 审核模式会在标题、工作区、设置和页脚持续显示标识，退出后才能使用正式后台。

## 权限边界

插件没有 content script，不读取 BOSS DOM、页面文本、Cookie、账号、密码或验证码，不自动搜索、滚动、翻页、打开候选人或发送消息。扫描使用 `activeTab` 与 `tabCapture` 将媒体流明确绑定到用户当前打开的 BOSS 标签页，不使用屏幕共享选择器。关键帧和标签页流不在后端文件、数据库、Chrome 存储或日志中持久化。当前分发版只允许访问 `localhost` 和 `127.0.0.1` 后端。

## 检查与打包

```bash
pnpm extension:assets
pnpm extension:check
pnpm extension:pack
```

打包产物为 `artifacts/hunting-extension-v0.7.2.zip`，SHA-256 位于同名 `.sha256` 文件。
