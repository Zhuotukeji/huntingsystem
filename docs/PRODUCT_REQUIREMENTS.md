# AI 自主复盘与竞品情报系统 V2.0 PRD

版本：V2.0

产品形态：内部招聘经营系统 + Chrome MV3 独立工具窗口插件

适用场景：单组织内部招聘、人才寻访、竞品公司与项目情报

## 1. 产品定义

系统保留 V1.6 已实现能力，升级为“人才寻访执行 + 公司项目情报 + AI 自主复盘”的内部经营系统。

核心闭环：

`高质量简历 -> 证据提取 -> 人才/公司/项目图谱 -> 搜索策略 -> BOSS 人工执行 -> 联系及招聘结果 -> 全链路归因 -> AI 复盘 -> 新策略版本`

目标用户为招聘负责人、HR 和系统管理员。V2.0 不包含自动发送 BOSS 消息、自动发送邮件、Offer/录用自动决策和无人值守抓取 BOSS；邮件营销和人才池自动再激活进入 V2.1。

核心经营指标：

- 每 100 个搜索结果产生的高质量候选人数。
- 高质量候选人有效沟通率、面试率、Offer 率和入职率。
- 从搜索任务创建到首次有效回复的中位耗时。
- 当前 AI 策略相对上一版本的实际增益。
- 公司正式情报覆盖率、证据冲突率和陈旧率。
- 垃圾信息拦截率、隔离复核覆盖率和优质简历误杀率。
- 任务反馈覆盖率、来源任务归因覆盖率等数据完整性指标。

## 2. 核心需求

### 2.1 全链路事件与归因

- 使用统一事件流记录任务生成、领取、开始搜索、扫描、入库、联系、回复、推进、淘汰、面试、Offer、入职、策略调整和简历质量复核。
- 每个候选人关联来源搜索任务、公司、关键词、策略版本和实验分组。
- 插件扫描自动继承当前搜索任务、策略版本和实验分配，避免 HR 重复选择来源。
- 候选人状态变更记录操作者、前后状态、原因、时间和幂等键。
- 已推进至后续阶段的候选人在重建或增量学习时不重新评分、不回退状态；后续结果继续参与策略归因。
- 招聘漏斗按 `person_id` 和事件类型去重；重复操作不得重复增加同一阶段人数。

### 2.2 简历质量与证据治理

- 保留隔离线、图谱准入线、高可信线和搜索任务阈值。
- 低质量简历只进入隔离区，不参与公司事实、关键词和搜索策略学习。
- 隔离简历支持人工“确认隔离”或“标记误拦截并重新学习”，两种结论均写入不可变审计记录。
- 人工恢复只允许重新进入学习流程，不绕过原文证据校验；重新解析后仍不满足图谱要求时转为 `NEEDS_REVIEW`，不得直接污染图谱。
- 所有公司、项目和人才结论区分 `FACT`、`INFERENCE`、`PREDICTION`、`DISPUTED`。
- 来源分为官方/政府、主流媒体/客户案例、招聘及行业资料、聚合及社交信息四级。
- 官方明确事实，或至少两个独立来源且包含一个高可信来源、综合置信度不低于 80 时，自动晋升正式事实。
- 冲突信息不得覆盖旧事实；冲突双方进入冲突层并触发重新研究。预测只能形成搜索假设，不能作为正式事实展示。
- 当前业务默认 180 天过期，招聘信号 60 天、项目状态 90 天；历史事实不自动过期，阈值可配置。

### 2.3 公司与竞品项目情报

- 维护竞品业务项目、业务线、产品线、区域单元和组织事件。
- 项目类型包括客户交付、招投标、产品落地、区域扩张、新业务启动和重大组织调整。
- 项目关联公司、业务线、地区、时间、产品、关键人员、技能需求、项目状态和证据。
- 高质量简历发现新公司、新项目或重要业务变化时自动创建研究任务。
- 公司情报过期、来源冲突或周复盘发现证据缺口时自动补充研究。
- 项目事实置信度不低于 80、人才需求推断不低于 70，且项目事实已经由合格来源晋升时，才允许生成新搜索任务。

### 2.4 模型联网研究

- 复用现有 AI Provider，不新增第三方搜索服务。
- 仅在 Provider 支持 Responses API `web_search` 工具且能力检测通过时启用联网研究。
- 能力不可用时任务进入 `BLOCKED_CONFIGURATION`，不得伪造搜索结果或无引用生成结论。
- 保存来源 URL、标题、发布日期、引用片段、采集时间和内容指纹，默认不保存完整网页。
- 默认每家公司同一主题 7 天内不重复研究；并发 2 个、每天最多 30 个研究任务，均可配置。
- BOSS 页面只允许 HR 主动操作，联网研究不得用于自动抓取 BOSS。

### 2.5 策略版本与搜索任务

- 使用不可变策略版本保存目标公司、关键词组、地区、优先级、搜索阈值、招呼语策略和生成依据。
- 人才画像硬条件、排除条件和业务目标只能由人工修改，AI 不得自动改写。
- AI 每次自动调整单项权重最多 0.08，权重范围保持 `0.65-1.35`。
- BOSS 搜索任务最多提供 4 个短职位词，每个不超过 16 个中文字符；公司、地区、经验条件分别展示，禁止描述性长句和多条件长尾关键词。
- AI 可自动创建、排序、延后、暂停重复或持续低效的内部搜索任务。
- 外部消息发送、永久淘汰、面试、Offer 和录用仍需人工确认。

### 2.6 复盘与实验

- 每日复盘检查任务吞吐、失败、重复任务、数据完整性和情报陈旧度。
- 每周复盘使用最近 28 天数据，比较公司、关键词、职位词、地区、话术和策略版本贡献。
- 单一策略维度至少需要 5 个完成任务且累计 30 个搜索结果，才允许自动调整；不足时只能生成探索任务。
- 默认 80% 任务执行当前最优策略，20% 用于探索新公司、关键词或话术。
- 首期以高质量候选率和有效沟通率为主要学习信号；面试、Offer 和入职作为延迟高价值结果回流。
- 新策略连续两个完整周期下降超过 20%且达到最低样本量时自动回滚并记录原因。
- 所有复盘保存输入窗口、指标快照、诊断、建议、自动应用内容、模型、成本和回滚记录。

### 2.7 产品界面

- 首页提供 4 个经营摘要：每百结果高质量人选、高质量人选有效沟通率、首次有效回复中位耗时、当前策略实际增益。
- 新增“数据分析”页面，支持按寻访战役和 7/28/90 天窗口筛选。
- 数据分析页展示招聘漏斗、策略版本比较、公司和关键词贡献、情报健康度、简历质量、数据完整性和历史快照。
- AI 学习中心提供“复盘、策略版本、实验、运行记录”四个视图。
- 公司页面展示业务时间线、竞品项目、组织事件、证据来源、冲突和陈旧信息。
- 候选人详情展示来源任务、策略版本、推进时间线和归因结果。
- 简历库对隔离简历提供人工质量复核入口。
- 设置页提供自主权限、联网能力检测、研究预算、证据晋升和复盘参数。
- 插件展示当前任务和策略来源，只生成招呼语草稿，不自动发送。

### 2.8 经营数据口径

所有比率必须同时保留分子和分母。分母为 0 时显示“暂无”，不得显示 `0%`；策略样本未达门槛时显示“样本不足”，不得给出推测性增益。

| 指标 | 分子 | 分母 | 去重与时间口径 |
| --- | --- | --- | --- |
| 每百结果高质量人选 | `SUM(qualified_count)` | `SUM(result_count)` | 按反馈时间进入 7/28/90 天窗口，结果乘 100 |
| 高质量人选有效沟通率 | `SUM(effective_conversations)` | `SUM(qualified_count)` | 按搜索任务反馈汇总 |
| 联系、回复、面试、Offer、入职人数 | 对应事件的 `person_id` 数量 | 上一阶段人数 | 同一窗口内按 `event_type + person_id` 去重 |
| 任务至首次有效回复 | 每个任务的首次 `REPLY_RECORDED` 时间减任务创建时间 | 有可归因回复的任务数 | 展示小时中位数，不使用平均数掩盖长尾 |
| 策略实际增益 | 当前策略综合分减上一策略综合分 | 上一策略综合分 | 综合分 = 高质量率 45% + 高质量人选有效沟通率 55%；新旧两版均需至少 5 个任务和 30 个结果 |
| 正式情报覆盖率 | 至少有一条 `PROMOTED + FACT` 结论的战役公司数 | 战役公司总数 | 按公司去重 |
| 证据冲突率 | `DISPUTED` 结论数 | 战役公司全部证据结论数 | 按 `evidence_claims.id` 去重 |
| 证据陈旧率 | `STALE` 结论数 | 战役公司全部证据结论数 | 按 `evidence_claims.id` 去重 |
| 垃圾信息拦截率 | 新评估且进入 `QUARANTINED` 的简历数 | 新评估简历数 | 按简历创建及质量评估时间进入窗口 |
| 优质简历误杀率 | 人工复核为 `RESTORED` 的隔离简历数 | 已人工复核隔离简历数 | 每份简历在窗口内只取最新复核结论 |
| 任务反馈覆盖率 | 有反馈的完成任务数 | 完成任务数 | 完成状态为 `COMPLETED/NO_RESULT/LOW_QUALITY` |
| 来源任务归因覆盖率 | 带 `search_task_id` 的入库简历数 | 入库简历数 | 按 `resume_id` 去重 |
| 隔离复核覆盖率 | 已人工复核隔离简历数 | 隔离简历数 | 用于判断误杀率是否有代表性 |

公司与关键词贡献按高质量候选人数排序，同时展示任务数、搜索结果数、每百结果高质量人选和有效沟通数。一个任务包含多个关键词时，每个关键词都获得该任务的观察值，页面明确标注为“分别归因”，AI 自动调权仍遵守最低样本门槛。

### 2.9 快照与数据完整性

- Worker 每个上海自然日为所有活动战役生成 7、28、90 天快照。
- 同一 `campaign_id + business_date + window_days` 只保留一条记录；重复执行使用幂等更新。
- 快照保存完整指标、公司/关键词维度和数据质量诊断，供历史趋势、周复盘和策略回滚使用。
- 数据完整度由任务反馈覆盖、来源任务归因、隔离简历复核三个适用维度等权计算；无适用分母时显示“暂无”，不得显示 100。
- 缺少回复事件、缺少人工复核或策略样本不足必须形成可见诊断，不阻塞正常业务录入。
- 业务页展示实时计算值；历史趋势只使用已持久化快照，避免回填数据改写历史。

## 3. 数据与接口

核心数据表：

- `activity_events`：统一事件及候选人漏斗。
- `candidate_origins`：候选人与任务、关键词、公司、策略版本的多来源关系。
- `strategy_versions`：草稿、激活、替换、回滚状态及完整策略快照。
- `review_runs`：每日、每周、人工触发的复盘结果。
- `experiments`、`experiment_assignments`：实验方案、分组、样本和结果。
- `intelligence_sources`、`evidence_claims`、`claim_sources`：公开来源、引用、事实分类、有效期和冲突。
- `projects`、`business_units`、`organization_events`：竞品业务和项目时序图谱。
- `research_tasks`：联网研究队列、能力阻断、频控和运行状态。
- `analytics_snapshots`：战役、自然日和窗口维度的经营指标快照。
- `resume_quality_reviews`：隔离确认与误拦截恢复的人工审计记录。

API：

- `/api/activity-events`
- `/api/strategy-versions`
- `/api/review-runs`
- `/api/experiments`
- `/api/intelligence/research`
- `/api/intelligence/capability`
- `/api/projects`
- `/api/analytics`
- `/api/resumes/:id/quality-review`
- `/api/settings/autonomy`

现有候选人状态、搜索任务反馈和插件简历入库接口保持兼容，并增加 `searchTaskId`、`strategyVersionId`、`experimentAssignmentId`。数据分析复用 `dashboard.view`，简历质量复核使用 `resumes.manage`，手工生成快照使用 `reviews.manage`。

## 4. PostgreSQL 迁移与实施

- 生产环境使用 PostgreSQL 16、`pg` 连接池、参数化 SQL 和版本化迁移文件。
- UUID、时间、结构化字段分别使用 `UUID`、`TIMESTAMPTZ`、`JSONB`；用户邮箱和角色代码使用 `CITEXT`。
- Docker Compose 提供 PostgreSQL 健康检查和持久卷，Web 与 Worker 通过 `DATABASE_URL` 连接。
- SQLite 迁移命令以只读方式打开源库，支持 `--dry-run`、一致性备份、逐表数量比对、外键校验和关键内容哈希校验。
- 采用一次停机切换，不长期双写；迁移失败时 PostgreSQL 事务回滚并保留迁移前 SQLite 备份。
- `users`、密码哈希、角色、权限、`ai_settings`、插件配置和加密值原样迁移，不重置用户名、密码或 AI 配置。
- `001_v2_initial.sql` 用于全新 V2 环境，`002_analytics_snapshots.sql` 为已部署 V2 环境增量增加经营快照和质量复核表。

迁移命令：

```bash
pnpm db:migrate:postgres -- --source .data/hunting.db --dry-run
pnpm db:migrate:postgres -- --source .data/hunting.db
```

## 5. 测试与验收

- SQLite 全量迁移后，各表数量、关系、用户权限、加密配置和简历内容指纹一致。
- 任一候选人可从最终状态追溯至原始简历、搜索任务、关键词和策略版本。
- 隔离简历不能污染图谱、公司事实或搜索任务；人工恢复后仍必须通过原文证据校验。
- 单一弱来源、冲突来源和预测内容不能自动成为正式事实。
- 模型不支持联网时研究任务明确阻断，不产生无引用情报。
- 未达到样本门槛时不自动改权重，页面不显示虚假策略增益。
- 重建图谱不会覆盖人工或自动推进后的候选人状态。
- 经营指标在空分母时显示“暂无”，所有比率可追溯分子和分母。
- 同一战役、日期和窗口重复生成快照后仍只有一条记录。
- 人工隔离复核可审计，误杀率只使用真实人工复核结论。
- 插件不自动抓取、翻页、发送消息或保存 BOSS 原始截图。
- 所有自动动作可审计、可暂停、可回滚；所有高影响外部动作保持人工确认。
- 发布前通过单元测试、迁移测试、API 集成测试、插件测试、权限测试、ESLint、TypeScript 和生产构建。

默认假设：V2.0 首期完成自主复盘、竞品项目情报和经营数据闭环；PostgreSQL 成为唯一生产数据库；系统继续服务单组织内部招聘场景。
