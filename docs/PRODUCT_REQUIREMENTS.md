# BOSS 人才情报与公司人才图谱系统 PRD

版本：V1.5（Chrome 插件 V0.6）
适用组织：50-200 人互联网公司  
首个画像：海外项目负责人  
产品形态：内部招聘系统 + Chrome 侧边栏插件

## 1. 目标

把主动招聘中最耗时的“找哪些公司、用什么关键词、看哪些人”变成可积累的组织能力。系统以合法取得的简历为事实源，建立公司、人才、职位、技能之间的证据图谱，持续生成下一轮 BOSS 人工搜索任务，并以“高匹配有效沟通人数”作为首要效果指标。

目标不是无人值守抓取 BOSS，而是让 HR 在平台允许的人工操作范围内，把每一次搜索和沟通变成下一轮可复用的数据。

## 2. 用户与口径

- 招聘负责人：配置人才画像、审核公司与学习建议、查看寻访效果。
- HR：通过网页端导入授权简历或通过插件扫描 BOSS 简历、执行搜索任务、主动使用截图判断、回填结果。
- 系统管理员：配置 Sub2API、插件访问码、截图功能开关和数据治理参数。

有效沟通定义为：候选人达到画像门槛、没有硬性排除项、产生有效回应，并完成与岗位相关的实质性双向沟通。原始打招呼数量不作为效果指标。

## 3. 产品闭环

1. 简历进入系统并记录来源类型、处理依据、创建人和哈希，按公司要求永久保留。
2. 每天北京时间 00:00 或人工触发增量学习。
3. AI 从简历中抽取人物、公司、任职、职位、技能、业务标签和画像证据。
4. 系统进行实体归一，更新带来源、可信度和时间戳的图谱关系。
5. 系统按人才画像、公司人才密度和历史反馈计算公司优先级。
6. 系统生成公司名、职位同义词、地区和执行说明组成的 BOSS 搜索任务。
7. HR 在本人已登录的 BOSS 网页中手工搜索、查看和沟通。
8. HR 回填结果数、合格数、有效沟通数和偏差说明。
9. 系统小步更新有上下限的搜索权重，样本充分后产生人工审核建议。

## 4. 功能需求

### 4.1 简历库

- 支持 PDF、DOCX、TXT、Markdown 和粘贴文本。
- 默认页面为可搜索、可筛选的候选人档案列表；只有点击“新增简历”后才显示导入与识别模块。
- 列表可展开查看候选人基本信息、任职经历、技能、来源依据、学习状态和内容指纹。
- 单文件上限 10MB，正文上限 20 万字符。
- 按人才画像和正文 SHA-256 哈希去重。
- 必须填写来源类型和处理依据。
- 状态包括待学习、处理中、已入图谱、需复核和失败。
- 记录分析版本、最后分析时间和错误信息；简历永久保留。
- 支持导入后立即学习，也支持只进入待处理队列。

验收：相同画像下重复导入同一正文只产生一条档案；无法提取有效正文时不入库；任何简历都可追溯来源和处理依据。

### 4.2 AI 学习任务

- 支持增量学习和全量重建。
- 增量只处理新增、失败、需复核或分析后发生变化的简历。
- 全量重建重新分析指定画像的全部简历。
- 每次运行保存画像快照、范围、阶段、输入输出水位、指标、错误和触发人。
- 单份简历失败不阻断其他简历，运行结果可为部分成功。
- Worker 每个北京时间自然日只创建一个午夜任务；服务重启后补跑当天任务。

验收：重复重建不会重复创建任职和技能关系；同一天只能存在一个午夜运行；运行记录能定位具体失败简历。

### 4.3 公司与人才图谱

- 节点包括人物、公司和技能。
- 关系包括现任、曾任和掌握技能。
- 任职和技能边必须关联来源简历、可信度、首次与最后发现时间。
- 公司事实包括别名、行业、业务标签、市场和渠道，事实保留来源。
- 公司实体先做标准化名称精确匹配；不确定合并不自动执行。
- 人物默认以简历档案为边界，不能仅凭同名自动合并。
- 提供公司人才总数、负责人/管理岗位关系数和画像分。
- 公司发现只使用授权简历中的任职关系，不再提供 InsightTracker 调研导入或独立公司发现智能体入口。
- 公司默认以列表展示，支持搜索、状态筛选、批量审核和展开查看简历证据、职位、市场、渠道及未知项。

验收：页面显示的每条关系都能映射到已授权简历；没有任职公司的简历进入“待核实任职公司”，不会猜测公司。

### 4.4 搜索任务

- 基于图谱公司、画像岗位、简历中出现的职位和通用负责人同义词生成任务。
- 每个任务包含公司、关键词、地区、经验建议、生成原因、证据摘要和预期候选人。
- 任务按公司画像分和反馈权重排序，优先级范围 1-100。
- 同一画像、公司、关键词组合在同一月份内去重。
- 状态包括新建、领取、执行中、完成、无结果、低质量、延期、过期和取消。
- HR 可复制搜索词、打开 BOSS 并回填结果。

验收：没有公司证据时不生成公司搜索任务；任务不包含自动翻页、自动打开或自动发送动作。

### 4.5 反馈与持续学习

- 反馈字段为结果数、符合画像数、有效沟通数和备注。
- 每家公司维护样本数、正向值和透明权重。
- 使用带先验的比例估计避免小样本极端值。
- 单次更新最多变化 0.08，总范围限制为 0.65-1.35。
- 至少 3 个样本后才生成公司信号建议。
- 公司合并、画像硬条件、排除条件和联系动作不得由反馈自动修改。

验收：单次异常反馈不能让公司权重越界；所有权重变化可由反馈记录重算。

### 4.6 Sub2API 配置

- 支持运行时配置 Base URL、模型、API 格式和 Key。
- 默认模型为 gpt-5.6。
- 支持 Chat Completions 和 Responses API 两种兼容格式。
- 提供连接测试与延迟显示。
- Key 使用 AES-256-GCM 加密，接口只返回掩码。
- 生产环境必须提供稳定的设置加密主密钥。

### 4.7 Chrome 插件

- 采用 Manifest V3 侧边栏，不注入 content script。
- 使用内部邮箱和插件访问码换取 7 天会话。
- 自动探测并固定连接 `localhost:3000`；升级后忽略旧端口缓存，不允许在插件内改用其他端口。
- 显示开放搜索任务、优先级、关键词、地区和执行状态；支持领取、开始、延期和结果反馈。
- 可复制搜索词并由用户打开 BOSS 页面。
- 只在 HR 点击后截取当前可见 BOSS 标签页。
- 截图分析只返回候选人代号、可见职位/公司/技能、判断、证据和未知项。
- 原始截图不写入数据库、文件系统或日志。
- 可基于可见事实生成个性化招呼语草稿，发送动作始终由 HR 完成。
- 截图分析展示候选人评分、判断、可见证据和未知项；服务端再次验证 BOSS 页面来源。
- 内置不含真实个人数据的合成 BOSS 样式页面，用于首次截图链路验收。
- 插件不提供 PDF、DOCX、TXT 或粘贴文本导入；这些入口只保留在网页端简历库。
- 插件支持 BOSS 简历详情的逐帧扫描：HR 从顶部点击开始，每滚动到一个需要保留的位置点击侧边栏的“截取当前帧”，再点击完成；插件不自动滚动、自动截图或读取页面 DOM。
- 扫描使用 `tabCapture` 按标签页 ID 定向捕获经过校验的活动标签页，不使用可能选中侧边栏的屏幕共享回退；开始时取得的画面只用于取景确认，不计入帧，后续画面仅由侧边栏截图按钮触发且只存在于内存，不生成、保存或上传视频文件。
- 每次有效点击“截取当前帧”都计为一帧，扫描最长 60 秒、内存最多缓存 30 帧；完成时均匀筛选最多 10 帧发送至 Sub2API。
- 真实 BOSS 页面在开始扫描时一次性确认本次数据、目的和接收方；切换标签页或候选人会停止扫描。
- 完成识别时按序合并，移除相邻重叠，校验候选人姓名和页面一致性，清除电话、邮箱、微信、证件号等非必要字段，随后创建永久简历和 `UPLOAD` 增量学习任务。
- 设置页支持保存并校验 Chrome Web Store 详情页地址；配置后以“安装到 Chrome”为主入口，并检测当前浏览器是否已安装及版本是否匹配。
- Chrome Web Store 可使用“未公开”发布方式；浏览器强制的安装确认不可绕过。未配置商店时才展示分发 ZIP、SHA-256 和开发侧载说明。
- 插件只接受来自 `localhost` 和 `127.0.0.1` 的外部版本探测消息，不向网页暴露任务、会话或候选人数据。
- 提供无需账号、本地后台、Sub2API 或 BOSS 登录的 Chrome Web Store 审核模式：所有公司、人才、任务、判断和草稿均为插件内置合成数据；截图仅限内置合成页并在内存中处理；扫描复用真实关键帧采集控件，但不上传、不入库且退出后重置。
- 审核模式必须在工作区、连接状态、设置页和页脚持续显示，禁止访问真实 BOSS 页面或调用正式 API，避免审核员误将合成结果理解为生产分析。
- 提供 `extension:check` 与 `extension:pack`，生成版本化、可校验的分发包。

### 4.8 精简后的信息架构

- 主导航不再展示“调研导入”和“智能体任务”。
- AI 运行审计统一收敛到“AI 学习中心”，外部平台人工执行统一收敛到“BOSS 搜索任务”和 Chrome 插件。
- 底层任务记录继续保留用于重试、审计和故障排查，不作为 HR 的独立工作页面。

## 5. 数据模型

核心表包括：

- 人才画像：campaigns、profile_versions。
- 简历：resume_documents。
- 图谱节点：people、organizations、skills。
- 图谱事实：employments、person_skills、organization_facts、graph_edges、evidence。
- AI 运行：ai_runs、ai_run_items。
- 搜索闭环：search_tasks、search_task_feedback、learning_weights、learning_recommendations。
- 配置与插件：ai_settings、plugin_sessions。

SQLite 用于本地试点。生产扩展到多人并发和高可用时迁移 PostgreSQL；简历原件迁移到带服务端加密和生命周期策略的对象存储。

## 6. AI 可靠性

- 结构化输出使用 Zod 验证，字段超限或格式错误视为失败。
- 提示词明确只抽取简历事实，不使用年龄、性别、婚育等敏感信息评分。
- 每个技能和任职关系带可信度及证据。
- 未配置模型时只解析具有明确“姓名、职位、任职行”格式的文本；无法可靠解析则失败，不产生虚构实体。
- 模型输出不能直接修改硬画像、自动合并实体、拒绝候选人或发送消息。
- 学习任务可重跑，关系按来源简历先删除后重建，保持幂等。

## 7. 安全与平台边界

- 系统不管理 BOSS 账号池，不保存 BOSS 密码、Cookie、验证码或浏览器会话。
- 不自动搜索、滚动、翻页、打开候选人、读取页面 DOM 或发送招呼。
- BOSS 简历只在 HR 明确确认处理依据并主动开始扫描后识别；真实扫描在开始时确认一次，关键帧和视频均不持久化。
- 插件令牌仅保存哈希，支持过期和撤销字段。
- API Key 和插件访问码以密文存储。
- 截图功能默认关闭，由管理员显式启用。
- 生产环境必须增加企业登录、角色权限、审计日志和备份；永久保留策略仍需支持候选人撤回授权时的合规删除流程。

## 8. 非功能要求

- 一份 6 万字符以内简历的模型请求超时 60 秒，失败可单份重试。
- SQLite 启用 WAL、外键、5 秒忙等待。
- 所有写入任务具有唯一键或内容哈希，避免重复。
- 页面适配 360px 移动宽度和常见桌面分辨率。
- Web、Worker 可在同一 Docker Compose 中共享持久卷。
- 关键逻辑必须有自动化测试，发布前通过 lint、test、生产构建和浏览器验收。

## 9. V1 验收

- 新部署中公司和人才数量均为 0，不展示无法追溯的演示数据。
- 导入一份结构化授权简历后，可看到人物、至少一家公司、任职关系和技能关系。
- 同一简历重复导入和全量重建不会产生重复关系。
- 学习完成后至少生成一个可执行的 BOSS 搜索任务。
- 反馈任务后公司权重发生受限变化。
- 设置页可保存 Sub2API 和插件访问码，数据库中不存在明文 Key。
- 插件能登录、拉取任务、复制关键词，并且只在用户点击时分析当前可见 BOSS 截图。
- 在没有本地后台、BOSS 账号和 Sub2API Key 的环境中，审核员可进入商店审核模式并完成合成任务领取、演示页截图判断、招呼语草稿、滚动扫描和本地合成识别；全过程没有网络上传或持久化。
- 配置有效 Chrome Web Store 地址后，设置页显示“安装到 Chrome”入口；安装完成后可检测插件版本，非法商店域名或无效扩展 ID 无法保存。
- 招呼语只作为可复制草稿存在，没有自动发送能力。
- 插件能通过开始/完成两个动作扫描合成长简历，筛选关键帧、去重合并后永久入库并自动创建增量学习队列；重复帧、混合候选人和重复简历不会重复入队。
- `extension:check` 通过，最终 ZIP 可解压并作为 MV3 插件加载，校验值与 `.sha256` 文件一致。
